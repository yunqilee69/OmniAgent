# ADR-0001：先做权限层，沙盒后置

状态：已采纳（M1） · 2026-10

## 背景

agent 要有用，就得能读写文件和跑命令；能跑命令就有破坏力。可选的防护有两类：

1. **权限**：执行前问一句「要不要跑」，用规则决定问不问。
2. **沙盒**：执行时用 OS 原语限制进程能碰什么。

两类都有必要，但一个人不可能同时做对。需要决定先做哪个。

## 候选方案

**A. sandbox-first（Codex 的路子）**：默认把命令关进沙盒，沙盒内自由，越界才问。
- 优点：默认姿态最安全，用起来最顺（大部分操作不打断）。
- 缺点：沙盒是平台相关的硬工程。macOS 的 Seatbelt profile 语法、Linux 的 bwrap 挂载顺序、seccomp、symlink 遮蔽、`/dev/null` 遮蔽技巧——任何一项都能吃掉一两周，而且写不出像样的单测。在沙盒能跑之前，整个 agent 都跑不起来。

**B. permission-first（Claude Code 的路子）**：先做规则和确认流程，沙盒作为可选叠加层。
- 优点：纯逻辑，一个下午能写完，能全量单测，能立刻跑起来看完整链路。
- 缺点：规则不是安全边界（`shell(curl *)` 拦不住 `/usr/bin/curl`），在沙盒缺失期间防护是软的。

## 决定

采用 **B**，并把 shell 工具的上线时间绑定到沙盒完成：

- M1 只有只读/写入/列目录三个工具，全部受权限门约束。
- **shell 工具不单独裸奔**，它和沙盒一起在 M3 上线。
- 权限求值写成纯函数 `decide(call, mode, rules, cwd)`，不读文件、不发网络、不问人。

## 后果

- 好处：M1 当天就能跑通「模型 → 工具 → 权限 → 执行 → 回灌」的完整链路，且有 19 个单测保护。权限层后面完全不用改就能被沙盒复用（沙盒只是 `allow` 之后换一个执行器）。
- 代价：在 M3 之前，agent 的破坏力上限是「改坏工作区里的文件」——这个风险对个人项目可接受。
- 附带决定：`resolveInside()` 只做字符串越权检查，不解析 symlink。这个洞记在 README 的「已知缺口」里，M3 用挂载遮蔽补。

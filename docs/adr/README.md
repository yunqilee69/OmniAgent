# 架构决策记录（ADR）

一篇一个决定。格式固定四段：**背景 / 候选方案 / 决定 / 后果**。

写 ADR 的门槛是「这个决定以后可能被质疑」。如果你能想象三个月后自己问「当初为什么这么搞」，
就值得写一篇。不要为显而易见的实现细节写 ADR。

| 编号 | 决定 |
| --- | --- |

| [0003](0003-tui-visual-hierarchy.md) | TUI 用角色调色板 + 三块左缘，不引入全屏终端框架 |
| [0004](0004-file-preview-viewers.md) | 文件预览用字节通道 + 扩展名分派，不引第三方渲染库 |

已否决 / 暂缓的候选也记在对应 ADR 里，别单独建文件。

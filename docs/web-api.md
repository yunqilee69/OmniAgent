# Local Web API

The Web server listens on `127.0.0.1`. The `Host` header must identify the listening loopback host and port. If an `Origin` header is present, it must match the normalized request Host origin, including hostname and port; `localhost` and `127.0.0.1` are not interchangeable. JSON requests require `Content-Type: application/json` and are limited to 64 KiB. Errors have the form `{ "error": "..." }`.

## Workspaces

- `GET /api/workspaces` returns `{ workspaces }`.
- `POST /api/workspaces` accepts `{ path, name? }` and returns `{ workspace }`. The path must be an absolute, existing directory; its real path is stored and duplicate paths resolve to the existing record.
- `DELETE /api/workspaces/:workspaceId` unregisters a workspace and returns `{ removed: true }`. It does not delete the directory or its sessions. It returns `409` while a turn or persistent session creation is active.

Workspace IDs are opaque. All session endpoints resolve the workspace ID through the registry rather than accepting a filesystem path from the caller.

## Permission Settings

- `GET /api/settings/permissions` returns `{ settings: { defaultPreset, requiresSelection } }`.
- `PUT /api/settings/permissions` accepts `{ defaultPreset }`, where the value is `read-only`, `workspace-write`, or `danger-full-access`; it returns the same envelope as GET.

This is a global default for genuinely new sessions, persisted under `dsh.permission.defaultPreset` in `~/.omniagent/config.json`. Existing sessions keep the preset recorded in their own event history. If configuration contains only legacy `mode` or `permissions` fields, GET reports `{ defaultPreset: null, requiresSelection: true }` until a DSH preset is explicitly selected. Legacy fields are retained for compatibility and are never translated into a DSH grant. Unrelated config fields are preserved. A failed write or detected external change does not update the service's trusted snapshot. Workspace-provided configuration is not loaded by this API.

The presets are:

- `read-only`: file mutations are rejected by the file fence; shell commands run with a write-denying OS sandbox when a supported backend is available.
- `workspace-write`: file mutations are allowed inside the workspace and the configured temporary roots without per-call approval; shell runs with those write roots. A requested wider sandbox can be approved for one call.
- `danger-full-access`: no DSH file sandbox is applied and the approval policy is `never`. This does not mean that explicit approval requests are automatically approved.

The file fence resolves symlinks for `read_file`/`list_dir` and rejects out-of-workspace physical targets; built-in writes reject hard-linked mutation targets. The shell preflight rejects pre-existing hard links in workspace and additional writable roots, but not under host temp roots. Path checks can race with hostile concurrent filesystem changes (TOCTOU). Seatbelt, bubblewrap, and Landlock constrain file writes only; they do not isolate network access, restrict all reads, or form a complete OS security boundary. A confined shell can still read files available to the current OS user, including configuration and credentials, and may be able to reach the loopback Web control plane. Clearing selected environment variables is not credential isolation. Confined shell execution fails closed if no usable supported backend is available.

## Sessions

- `GET /api/workspaces/:workspaceId/sessions` returns workspace-local `{ sessions }` summaries. A subagent summary also includes `parentSessionId`, `depth`, and `description` when recorded in its header.
- `POST /api/workspaces/:workspaceId/sessions` accepts `{}` and returns `{ session }`. A fresh session receives the configured global permission default and the configured default model when available; otherwise its permission is unset until selected.
- `GET /api/workspaces/:workspaceId/sessions/:sessionId` returns `{ header, permission, model, plan, todos, messages, events, trajectory, audit }`; `permission` is `{ preset }`, where `preset` is one of the three DSH values or `null` for a legacy/invalid/unselected history, `model` is the persisted `{ version, provider, model, reasoningEffort? }` selection or `null` for a legacy session without a selection event, `plan` is `{ active }`, and `todos` is the latest whole-list todo array or `null`. Subagent headers expose their parent/depth/description.
- `POST /api/workspaces/:workspaceId/sessions/:sessionId/permission` accepts `{ preset }` and persists a `permission/dsh-preset` event. It is idempotent for the current value. Legacy or invalid histories may be repaired only by this explicit selection. Workspace removal or a concurrent session creation can return `409`; a running turn continues with the immutable permission snapshot it captured at admission, and the updated choice applies to subsequent turns.
- `POST /api/workspaces/:workspaceId/sessions/:sessionId/plan` accepts exactly `{ active: boolean }` and persists a `plan/mode` event. It is idempotent. An active turn, workspace removal, or concurrent session creation returns `409`; malformed input returns `400`. Plan mode supplies planning guidance and the `exit_plan_mode` tool, but it does not change the permission preset or enforce read-only file access.
- `POST /api/workspaces/:workspaceId/sessions/:sessionId/plan-review` accepts `{ requestId, approved, feedback? }` and settles the live plan-review request. `feedback` is optional and bounded to 4,000 characters. Stale, duplicate, or wrong-session requests return `409`; malformed input returns `400`.
- `GET /api/models` returns `{ models }`, a credential-free catalog of `{ provider, model, name, contextWindow?, reasoning? }` entries the current configuration can construct.
- `POST /api/workspaces/:workspaceId/sessions/:sessionId/model` accepts `{ provider, model, reasoningEffort? }` and persists a `model/selected` event. Unknown catalog members return `409`; malformed or extra fields return `400`; an active turn or workspace removal returns `409`. It is idempotent for the current selection.
- `GET /api/workspaces/:workspaceId/sessions/:sessionId/events` returns `{ events }` with the same allowlisted trace projection. Known trace types include lifecycle, tool, permission, compaction, and error events; unknown types and stored call IDs are omitted. Event details contain only validated metadata, not arguments, output, rules, or error text.
- `GET /api/workspaces/:workspaceId/sessions/:sessionId/audit` returns `{ audit }` for that session, without argument digests or permission rule source text. It can include tool names and call IDs.
- `GET /api/workspaces/:workspaceId/sessions/:sessionId/export?format=markdown|json` downloads a transcript for that session. JSON format is `omniagent-session-transcript`, version 1, not a resumable session log or DSH ZIP/JSONL archive. Both formats exclude system/injected context, tool arguments, permission and audit records, and image bytes, but include conversation text and stored tool output, which may contain secrets or paths. They do not include descendant sessions or attachments. Review exports before sharing.
- `POST /api/workspaces/:workspaceId/sessions/:sessionId/interrupt` accepts `{}` and interrupts an active turn. It returns `404` for an unknown session and `409` when a known session has no active turn.
- `POST /api/workspaces/:workspaceId/sessions/:sessionId/approvals` accepts `{ requestId, decision }`, with `decision` equal to `allow` or `deny`, and returns `{ ok: true }` for a current request. `allow` applies once. Stale, duplicate, or wrong-session requests return `409`; invalid input returns `400`.

Unknown workspaces and sessions return `404`. A session ID in one workspace does not select a session with the same ID in another workspace. Session files saved under a historical non-canonical workspace spelling are not guessed or migrated into a canonical workspace; the caller must continue using the original identity or perform an explicit migration.

`POST /api/workspaces/:workspaceId/sessions/:sessionId/messages` accepts `{ text }` and responds with `Content-Type: text/event-stream`. Each frame is `data: <AgentEvent JSON>\n\n` in runtime order. A request needing human confirmation emits a live `permission.requested` event containing a random request ID, the tool call's ID, name, and arguments, and a sanitized one-call escalation reason showing the target preset and caller justification; it is not persisted as a trace. In plan mode, `exit_plan_mode` emits a live `plan.review.requested` event with a random request ID and the complete Markdown plan; it is not persisted as a trace, and the turn resumes only after `plan-review`. A successful review also emits a live `plan.review.decided` event with the request ID, decision, and optional feedback. A normal or interrupted turn ends with `turn.end`; failures after streaming starts include an `error` and `turn.end` with reason `error`. Concurrent turns for one session return `409`. Cancellation, disconnection, interruption, timeout (normally 120 seconds), and errors deny an outstanding approval or plan review.

The turn may use these built-in collaboration tools: `bash`, `read_file`, `write_file`, `list_dir`, `skill`, `todo_write`, `exit_plan_mode`, `subagent`, `send_message`, `list_agents`, `wait_agent`, and `interrupt_agent`. Subagents are separate sessions in the same workspace and appear through the normal session list and detail endpoints; their completion notice is persisted on the parent (`subagent/end` and, when the parent is not live in that process, `subagent/notice`). Exports remain limited to the requested session and do not include descendant sessions.

The host is bound to loopback but does not authenticate local users. Host/Origin checks are browser-origin protections, not an authorization boundary for other local processes. During any active turn or session creation, new session creation and permission/model/plan changes are rejected with `409`; this prevents a running sandboxed command from changing a later turn's persisted preset, model, or plan guidance through the unauthenticated control plane, but it does not authenticate local processes or prevent them from using other allowed APIs. The live stream is the runtime event protocol, not a redacted export: assistant and tool events may include conversation text, tool arguments, and tool results. Treat it as private session data. Trace records and the trajectory projection deliberately exclude tool arguments and full tool output. The conversation log itself may contain both, and no claim is made that the log is suitable for sharing without review. Web audit records are written to `~/.omniagent/web-audit/<workspace-hash>.jsonl` and are filtered for the selected session; responses include at most the latest 1,000 entries and read only the last 2 MiB of the file. New audit files are private and may contain argument digests and permission rule text; the API exposes neither. TUI audit files remain in the workspace at `.omniagent/audit.jsonl`; a newly created directory is `0700` and a new file is `0600`, but pre-existing modes are left unchanged. A symlinked or non-regular audit target is rejected rather than followed. Another process running as the same OS user can still read these files. Existing workspace-local audit files are not automatically read or migrated by Web.
